## 1. 概要

**目的**

- 管理者がショップに登録済みの支払方法について、**表示名**、**手数料**、**注文金額に基づく利用条件**、および**ロゴ**を設定できるようにする。

**システム上の役割**

- ストアフロントでの支払方法の**表示方法**と**選択条件**を管理する。実際の決済ゲートウェイ接続設定（GMO API、ショップ情報等）を**代替するものではない**。

**対象ユーザー**

- EC-CUBE管理画面にログイン済みの管理者。

## 2. スコープ

**スコープ内**

- URLの `id` に基づき、既存のpayment編集画面を開く。
- 支払方法名、手数料、利用可能な注文金額範囲の編集、ロゴのアップロード。
- 表示状態（**表示**ドロップダウン）の保存、および一覧への戻り。

**スコープ外**

- **Shop ID / Shop Pass / GMOエンドポイント**の設定 — 環境変数およびCustomizeコード（`GmoApiClient`）で管理。本フォームの対象外。
- 実際の決済フロー（EntryTran / ExecTran）およびフロントエンドでのカード処理。

## 3. 画面構成・機能

- EC-CUBE **ヘッダー**（ショップ名、管理者アカウント）。
- **左メニュー：** 店舗設定エリア。
- **メインコンテンツ：** **支払方法**フォーム（1つの支払方法）。
- **コンバージョンバー（ページ下部）：** 一覧へ戻る、表示状態選択、保存。

## 4. パラメータ・パス

| パラメータ | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| `id`（URL） | 数値 | あり | `dtb_payment` のレコードID。パス例：`/admin/setting/shop/payment/5/edit` → `id = 5`。 |

**アクセス条件**

| 項目 | 値 |
| --- | --- |
| URLの例（ローカル） | `http://localhost:8080/index.php/admin/setting/shop/payment/5/edit` |
| 権限 | EC-CUBE **管理画面**ログイン済み（**店舗設定**の権限あり）。 |

**メニュー遷移（サイドバー）**

- **設定** → **店舗設定** → **支払方法設定**
- ページタイトル：**支払方法設定** **店舗設定**

## 5. データソース

| ソース | 説明 |
| --- | --- |
| `dtb_payment` | 名称、手数料、利用条件、表示状態、ロゴ紐付け等。 |
| BaseInfo（ショップ） | ショップ共通コンテキスト（GMO API設定の代替ではない）。 |

備考：フォームデータはURLの `id` に依存。例えば **GMO Direct** の設定は8項を参照。

## 6. 画面状態

**6.1 初期表示**

- 現在のpaymentデータに基づきフォームが入力済み。
- ロゴエリアは未アップロードの場合は空欄。

**6.2 保存成功**

- **登録**ボタン押下後、EC-CUBE標準の成功メッセージを表示。

**6.3 バリデーションエラー**

- **必須**フィールドの未入力または不正な値：エラーを表示、修正後に再保存。

**6.4 該当しない状態**

- **編集**画面には常に1レコードが存在。一覧画面のような「空リスト」はない。

## 9. ビジネスロジック

- 注文合計が**利用条件**の範囲内 → チェックアウトの支払方法選択ステップに表示（手数料付き）。
- 上限が空欄 → 下限以上であれば制限なし。
- **表示** = 非表示 → レコードが存在していてもストアフロントに表示しない。
- **手数料**はEC-CUBEのルールに従う（計算式の詳細はEC-CUBEコアドキュメントを参照）。

## 10. イベント・処理

| イベント | システム動作 |
| --- | --- |
| 支払方法一覧をクリック | 一覧へ遷移 |
| 表示を変更 | 保存時に更新（フォーム設計に準拠） |
| 登録をクリック | バリデーション → `dtb_payment` を保存 |
| ロゴアップロード | EC-CUBEのファイル/メディア管理に従い保存 |

## 11. 画面遷移（フロー）

```
支払方法設定一覧
  → 一覧から1件の編集を開く
    → 編集画面（本ドキュメント）
      → 支払方法一覧 → 一覧へ
      → 登録 → 保存（画面に留まるかリダイレクトかはバージョンに依存）
```

## 12. 権限・アクセス制御

- **管理者**ログインおよび**店舗設定** / 支払方法編集の権限が必要。
- 管理画面に未ログインの場合、URLにアクセス不可。

## 13. 外部連携

- **GMO：** 本画面では設定しない。APIおよびクレデンシャルは **Customize**（`GmoApiClient`）と環境変数 `GMO_*` で管理。
- 管理画面はチェックアウトで顧客が正しく **GMO Direct** を選択し、適切な手数料/利用条件が表示されるようにする。

**GMO Direct 実装メモ**

- Shop ID、エンドポイント、モックモード等 → **環境変数** + コード。管理フォーム上には**存在しない**。
- **支払方法**フォームが管理するのは**名称、手数料、利用条件、ロゴ、表示状態**のみ。

技術参照：`app/Customize/README_GMO_DIRECT.md`。

## 15. エッジケース

- **下限 > 上限**（両方入力時）：バリデーションエラーの可能性あり。
- **ロゴ**のファイルサイズ/形式が不正：サーバー設定に基づくアップロードエラー。
- URLの **id** が存在しない：404 または該当エラーを返す。
- **名称の誤変更**：表示にのみ影響。決済クラスはEC-CUBEのpayment設定で管理。

## 16. ログ・監視

- 管理ログはEC-CUBEの設定に依存。
- **手数料**や**利用条件**を変更した後は、注文金額の境界値（0、閾値付近、高額）でチェックアウトのテストを推奨。

## 17. テスト観点

**主要フロー**

- 有効な URL + id → フォームがデータと一致（例：GMO Direct、手数料 300）。
- 編集して**登録** → リロード / 再度開く → 保存された値が反映されていること。

**エラー**

- 必須フィールドが空 → エラーメッセージが表示されること。
- ロゴが不正 → 明確なエラーが表示されること。

**エッジ**

- 上限が空欄 → 高額注文でも下限条件を満たせば支払方法が表示されること。
- **表示** = 非表示 → ストアフロントで選択不可になること。
